# Current limitations and work queue

This document separates the initial usable methods from extensions that need methodological and numerical decisions. Each entry has a stable identifier so subsequent changes can address one problem and its acceptance checks at a time. Model assumptions and formulae appear in [methods.md](methods.md); dependency findings appear in [curupixa-issues.md](curupixa-issues.md).

## Compatibility at version 0.2.0

| Combination | Current support | Restriction |
|---|---|---|
| Non-ultrametric tree + continuous ASR | Brownian ML and missing-tip predictions | Strictly positive lengths; at least two distinct exact observed values |
| Non-ultrametric tree + continuous PCM | PIC and Brownian PGLS | PIC bifurcating; PGLS dense; valid root and evolutionary scale |
| Non-ultrametric tree + unordered classes | Equal-rates CTMC and parsimony | CTMC fixed uniform frequencies; parsimony ignores lengths |
| Ordered natural-number states | Ordered parsimony | Unit cost per integer step; finite declared alphabet |
| Ordered likelihood, count response, ordinal PCM | Deferred | Requires a specified generator or observation/link model |
| Unrooted input | Explicit midpoint preparation | Biological root remains an assumption; Newick alone cannot establish it |
| No tree | Numeric Euclidean UPGMA | Descriptive, complete features, manually scaled units |
| Missing traits | Brownian likelihood/predictions, discrete unknowns, PIC observed subtree, PGLS complete cases | Explicit CLI/Python policy for omitted rows/keys; ignorable missingness assumptions |
| Polytomies | Brownian ASR, PGLS, CTMC, hard-polytomy parsimony | PIC rejects unary or multifurcating internal nodes |
| Zero branch lengths | CTMC, parsimony, inspection/preparation | Continuous methods reject them; impossible CTMC data return an error |
| Several traits | Independent CLI/API batches; multiple PGLS predictors and UPGMA features | No joint multivariate evolutionary covariance or borrowing between trait columns |
| Uncertain discrete observations | C/Python observation-likelihood vectors | Explicit likelihood semantics/alphabet; no soft-vector TSV format yet |
| Continuous measurement error | Deferred | Exact observed values are assumed; missing values have a different treatment |

## Rooting and temporal preparation

- **TREE-01: Additional rooting methods.** Midpoint rooting can fail under rate heterogeneity and sampling imbalance. Add outgroup edge rooting, minimum-variance rooting and, with dates, least-squares temporal rooting. Acceptance: known-root simulations, root uncertainty reporting, serial sampling tests and preservation of taxon distances. Nonreversible trait models would make likelihood sensitive to the chosen root; symmetric models generally cannot identify it alone.
- **TREE-02: General ultrametric optimisation.** The current terminal-extension routine solves a restricted linear programme with internal lengths fixed. Implement a separately named fixed-topology constrained fit that can change internal lengths, with an explicit objective (for example branch-length deviations under L1, or patristic deviations under least squares), nonnegative edges, constraints and convergence diagnostics. Acceptance: independent optimiser comparisons, exact small cases and changed-distance reports. A numerical projection by itself does not establish calibrated ages.
- **TREE-03: Dating and serial samples.** Support tip dates, calibrations, uncertainty and rate smoothing through a chosen objective. Extant ultrametric and fossil/serially sampled trees require different constraints. Acceptance: synthetic dated trees with recoverable times and explicit handling of incompatible calibrations.
- **TREE-04: Trait-derived trees.** UPGMA now accepts several CLI numeric features via plural predictors, as does the API. Add caller-supplied distances, categorical/mixed-type distances, scaling choices and uncertainty. Using the response to infer its own covariance structure creates circularity for inferential PCM. Acceptance: documented independent training features or a joint generative model, reproducible ties and missing-feature rules. Current selected features must be complete.
- **TREE-05: Unary and zero-length structures.** Continuous methods currently reject zero edges, and PIC requires an originally binary tree. Missing-tip PIC contracts the retained unary paths, but arbitrary unary input remains unsupported. Midpoint preserves labelled vertices, so it can produce unary nodes. Add explicit contraction/constraint handling while preserving observed taxa and annotations. Acceptance: degenerate covariance tests, contradictory exact observations and equivalence before/after permitted contractions. The former broad-polytomy append bottleneck is addressed through curupixa's builder.

## Trait and observation models

- **MODEL-01: Richer discrete CTMCs.** Add unequal stationary frequencies, symmetric unequal rates and asymmetric rates with an appropriate matrix exponential/backend. Ordered CTMCs need explicit adjacent-state transitions, boundary treatment and rate conventions. Acceptance: independently exponentiated generators, exhaustive tiny-tree marginals and parameter-identifiability checks. Current natural-number labels have ordered meaning only under ordered parsimony.
- **MODEL-02: Continuous evolutionary alternatives.** Add OU, early-burst, trends, rate regimes and transformed branch covariances such as Pagel's $\lambda$. Some require careful root distributions, temporal interpretation or ultrametric restrictions. Acceptance: analytic limiting cases, comparisons with established implementations and likelihood diagnostics at parameter boundaries.
- **MODEL-03: Ordinal, count, binary and non-Gaussian PCM.** Brownian PGLS is currently the regression model. Add phylogenetic generalised linear models or latent-liability models with declared links and observation distributions. Treating a count as continuous or a category code as a numeric measurement changes the model. Acceptance: calibrated simulated coverage and false-positive rates, including non-ultrametric trees and rare classes.
- **MODEL-04: Missingness, uncertainty and polymorphism.** Partly addressed in 0.2.0: Brownian missing-tip likelihood/prediction and discrete observation-likelihood vectors are available; PIC uses the observed subtree and PGLS uses complete cases. Remaining work includes continuous measurement error, within-taxon replication, censored observations, joint missing-predictor inference and non-ignorable missingness. Acceptance: exact-data limits, known-error covariance comparisons, marginalisation checks, uncertain-predictor simulations and explicit observation semantics. The [uncertainty guide](missing-data-and-uncertainty.md) separates implemented and proposed options.
- **MODEL-05: Multivariate traits and correlated evolution.** Add joint diffusion, discrete correlated evolution and models for high-dimensional metadata. Independent trait analyses do not estimate cross-trait evolutionary covariance. Acceptance: known covariance recovery and diagnostics when parameters exceed the information in the tree.

## Inference, interpretation and outputs

- **ASR-01: Joint likelihood reconstructions and histories.** Add a joint MAP traceback, MPPA-style summaries or stochastic mapping under an explicit probability model. Independently chosen marginal modes can conflict as a joint scenario. Acceptance: enumeration of joint optima and summaries that retain ambiguity.
- **ASR-02: Additional parsimony conventions.** Add user-defined costs, asymmetric costs, ACCTRAN/DELTRAN and scenario-weighted ambiguity summaries. Current ordered/unordered sets give possible states across all global optima; choosing all set members independently need not produce an optimum. Acceptance: exhaustive assignment checks and declared hard/soft-polytomy semantics.
- **INFER-01: Boundary and optimisation diagnostics.** The bounded ER rate search can return a boundary or plateau estimate; all-unknown traits contain no rate information. Add bound flags, profile curves, uncertainty and stopping diagnostics. Acceptance: boundary, multimodal, flat and weakly identifiable likelihood cases; compare a denser independent search. Fixed-rate ASR remains available.
- **INFER-02: Parameter and tree uncertainty.** ASR variances/probabilities condition on fitted evolutionary rates and one tree. Brownian ASR includes ancestral root-state uncertainty under a flat prior, while excluding uncertainty from estimating the diffusion variance. Add simulation/bootstrap or profile approaches, and propagation over user-supplied trees. Acceptance: coverage studies and clear separation of observation, parameter, topology and branch-length uncertainty. Bayesian methods and topology optimisation are intentionally deferred for a later phase.
- **PCM-01: Signal and model comparison.** Add selected signal statistics, covariance diagnostics, likelihood tests/model criteria and simulation-based calibration. Existing Brownian fits, contrasts and PGLS supply a starting point. Acceptance: null simulations on independently supplied trees and documented small-sample behaviour.
- **IO-01: Batch analysis and output provenance.** Partly addressed in 0.2.0: independent CLI trait batches, multiple CLI predictors/features, observed/used flags, missingness counts and batch manifests are available. Add fuller schema metadata, input fingerprints, machine-readable root/length-unit declarations and a soft-observation TSV format. State coding, root and length units remain user responsibilities. Independent columns do not form a joint evolutionary model. File prefixes replace existing files and require existing parent directories.

## Numerical, performance and packaging work

- **PERF-01: Tree-pruning GLS.** Dense PGLS takes $O(T^3)$ time and $O(T^2)$ memory. Replace or supplement it with a tree-based whitening solver for supported covariance models. Acceptance: coefficient, SE and log-likelihood parity against the dense solver and scaling benchmarks on large trees.
- **PERF-02: Reusable analysis workspaces.** ER rate fitting now reuses curupixa's prepared binding instead of repeating label mapping/validation. Brownian/PIC/discrete/parsimony kernels are delegated upstream and independent Brownian batches are available. Public Obuina calls still allocate owned results and per-call preparation. Add reusable application workspaces and shared preparation across batches while preserving immutable inputs. Acceptance: multiworker isolation, repeated-call memory checks and benchmarks separating mapping, fitting and output copying.
- **NUM-01: Extreme scales and boundary variances.** Finite inputs can still overflow intermediate depth/contrast/SSE calculations; ill-conditioned Brownian covariance can fail Cholesky. Very small variation can underflow a variance, and nearly exact regression fits can leave round-off residuals. Add carefully documented scaling/conditioning diagnostics and boundary-result semantics. Current functions return recoverable errors instead of committing failed results. Rescaling measurements and branch units is currently the user's responsibility.
- **API-01: Public ABI evolution.** Result structures are public and versioned as an initial 0.x API; callers must compile against the matching header. Introduce opaque or size-tagged configuration/result objects before promising stable cross-version ABI compatibility. Acceptance: installed C/C++ consumers and bindings tested across supported releases.
- **BUILD-01: Portability and distribution.** Linux/GCC is the tested target. macOS shared-library discovery/install paths and Windows exports/installers need validation. Add package metadata, CI and reproducible dependency provisioning after repository hosting is chosen. The default source dependency is the sibling curupixa checkout, whose tested commit is recorded in the dependency report.
- **VALIDATE-01: External cross-package comparisons.** Current numerical validation uses exhaustive enumeration and independently derived dense Gaussian/GLS calculations. Add reproducible reference runs with PastML, castor, ape, phytools and phangorn, matching root priors, rate normalisation, ML versus REML and hard-polytomy conventions. Passing internal reference tests does not establish equivalence to all defaults in those packages.
